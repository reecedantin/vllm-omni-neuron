## Introduction

[GR00T N1.7-3B](https://huggingface.co/nvidia/GR00T-N1.7-3B) is a vision-language-action (VLA) robot policy
developed by NVIDIA. It pairs a ~2B vision-language backbone ([Cosmos-Reason2-2B](https://huggingface.co/nvidia/Cosmos-Reason2-2B),
a Qwen3-VL post-train, of which GR00T keeps the first 16 of 28 decoder layers: `select_layer: 16`) with a
flow-matching diffusion action head (a 32-layer DiT, interleaved self- and cross-attention) that denoises a chunk of future robot actions in 4 Euler steps. Given camera frames, the
robot's own state (end-effector pose, gripper, joints) and a language instruction, it outputs a 40-step action
chunk; an embodiment-conditioned encoder/decoder lets one checkpoint serve many robot embodiments. There is no
image or video decoder in the inference path — the model is action-only.

GR00T N1.7-3B is now supported for inference serving with [vLLM Omni](https://docs.vllm.ai/projects/vllm-omni/en/latest/)
using the Neuron SDK on AWS Inferentia2 (`inf2`), Trainium1 (`trn1`) and Trainium2 (`trn2`) hardware. One
NeuronCore is enough: the whole model is ~5.9 GB in BF16.

**License:** [NVIDIA Open Model License](https://www.nvidia.com/en-us/agreements/enterprise-software/nvidia-open-model-license/).
`nvidia/GR00T-N1.7-3B` is a gated Hugging Face repo; request access and run `hf auth login` (or set `HF_TOKEN`)
before downloading.

**Compatible model checkpoints:**

| Model | HuggingFace | Hardware | Quantization |
|-------|-------------|----------|--------------|
| GR00T N1.7-3B | [nvidia/GR00T-N1.7-3B](https://huggingface.co/nvidia/GR00T-N1.7-3B) | Inf2, Trn1, Trn2 | BF16 |
| GR00T-H-N1.7 | [nvidia/GR00T-H-N1.7](https://huggingface.co/nvidia/GR00T-H-N1.7) | Inf2, Trn1, Trn2 | BF16 |

> GR00T-H-N1.7 is a surgical-robotics post-train of N1.7; see [GR00T-H vs N1.7](#gr00t-h-vs-n17) below. The
> plugin runs its model graphs, but serving it end to end also needs its own (non-upstream) processor —
> see that section for details.

## Features

| Category | Feature | Status |
|---|---|---|
| **Generation** | Action-chunk prediction (flow matching, 4 steps) | ✅ |
| | Multi-embodiment (embodiment-conditioned encoder/decoder) | ✅ |
| | Real-time chunking (RTC) inpainting from a previous chunk | - |
| **Quantization** | BF16 | ✅ |
| **Parallelism** | Tensor Parallelism (TP) of the action head | ✅ opt-in, `tensor_parallel_size: 2` or `4` |
| | TP of the backbone (vision tower + text decoder) | ✅ opt-in, `model_config.tp_backbone: true` |
| | Context / CFG Parallelism | n/a (no CFG, no long sequence) |
| **Performance** | Baked AdaLN modulation tables (fixed 4-step schedule) | ✅ |
| | Host fast path for the upstream processor (cached chat template / tokenization, batched image transform, vectorized action decoding) | ✅ |
| | Device cache of repeated host tables (mRoPE, masks, vision position taps) | ✅ |
| | Camera-count buckets for the vision graph (1, 2, 3, 4, 6, 8 images) | ✅ |
| | Vision + text as one graph (`GR00T_FUSED_BACKBONE=1`) | - (no measured gain) |
| | Fused self-attention Q/K/V in the action head (`GR00T_HEAD_FUSE_QKV=1`) | - (slower) |
| | Cross-attention K/V reuse across denoising steps | ✅ (no measured gain; compiler already shares it) |
| | NKI flash attention (vision tower) | - (slower than the plain path at this sequence length) |
| **Compilation** | torch.compile | ✅ |

**Status legend:**

- ✅ Supported: integrated and tested for GR00T N1.7.
- `-`: not supported / not enabled by default.

### Recommended configuration

One NeuronCore, `tensor_parallel_size: 1` (see [`gr00t_stage.yaml`](../../examples/gr00t/gr00t_stage.yaml) /
[`gr00t_stage_trn2.yaml`](../../examples/gr00t/gr00t_stage_trn2.yaml)). The model is small — 3.14B params,
5.86 GiB BF16 — so memory never requires sharding. For the lowest per-request latency, set
`tensor_parallel_size: 2` and two `devices:` ([`gr00t_stage_trn2_tp2.yaml`](../../examples/gr00t/gr00t_stage_trn2_tp2.yaml)): the action head (the weight-streaming-bound part, 32 DiT layers
x 4 unrolled Euler steps) is then split by attention head and feed-forward column over the two cores, while
the vision tower and text decoder stay replicated. With all four cores of a chip,
[`gr00t_stage_trn2_tp4.yaml`](../../examples/gr00t/gr00t_stage_trn2_tp4.yaml) also shards the backbone
(`tp_backbone: true`) and is the lowest-latency layout (see [Performance](#performance)). For throughput,
prefer one TP=1 replica per core. The two
stage files are identical: GR00T needs no per-hardware tuning, so `_trn2` is the recommended default and the
plain name is kept for parity with the other models' `<pkg>_stage.yaml` naming.

## Accuracy Evaluation

**Benchmark / gate:** normalized action-chunk MSE and cosine similarity against upstream vLLM-Omni's
`Gr00tN1d7` running fp32 on CPU, same processor inputs and the same seeded initial noise. Gate: MSE ≤ 1e-3,
cosine ≥ 0.999.

| Metric | Neuron (BF16, trn2) | CPU BF16 (reference) | Threshold |
|---|---|---|---|
| Action MSE vs upstream fp32 | 4.66e-4 | 6.9e-5 | ≤ 1e-3 |
| Cosine similarity | 0.99980 | 0.99997 | ≥ 0.999 |
| Relative L2 | 1.99% | 0.76% | — |

Served end to end (processor, graphs, decoding; same observation and noise; [`served_parity.py`](../../examples/gr00t/served_parity.py)):

| Served configuration | Action MSE vs upstream fp32 | Cosine | Relative L2 | Gate |
|---|---|---|---|---|
| TP=1, 1 NeuronCore | 4.79e-4 | 0.99980 | 2.01% | pass |
| TP=2 action head, 2 NeuronCores | 5.12e-4 | 0.99978 | 2.08% | pass |

Decoded DROID gripper positions amplify normalized-space error (the gripper range is wide relative to
its values): CPU BF16 alone already moves them 18% relative to fp32, while end-effector and joint actions
stay within 1.5% and 3.1% on device.

The Neuron error is ordinary inherited BF16 rounding, not a device-specific bug: per-stage error on device
tracks CPU BF16 error closely (vision 6.4% vs 5.3%, text hidden state 2.2% vs 2.1%), and the action head
alone, given FP32 backbone features, is 0.36% on device vs 0.44% on CPU.

The host-baked AdaLN modulation tables (see [Performance](#performance)) are bit-identical to the same
modulation computed in the compiled graph on device — checked across all 132 per-block/per-step rows with
[`test/neuron/test_gr00t_device.py`](../../test/neuron/test_gr00t_device.py).

**Reproduce:**

```bash
python examples/gr00t/run.py --model-path nvidia/GR00T-N1.7-3B --output actions.npz
pytest test/neuron/test_gr00t_device.py -q   # needs a Neuron device + GR00T_WEIGHTS
```

## Performance

### Comparison with NVIDIA's published benchmark

Same setup as NVIDIA's deployment benchmark
([Isaac-GR00T `scripts/deployment/README.md`, Performance](https://github.com/NVIDIA/Isaac-GR00T/blob/main/scripts/deployment/README.md#performance)):
checkpoint `nvidia/GR00T-N1.7-LIBERO` (`libero_10`), `demo_data/libero_demo` episode 0 step 0, embodiment
`LIBERO_PANDA`, 4 denoising steps, BF16, batch 1. NVIDIA's table says "1 camera"; its benchmark script feeds
the checkpoint's LIBERO_PANDA views, which are the scene camera and the wrist camera at one frame each (2
images, 156 prompt tokens), and so do we. Stages follow NVIDIA's split: data processing = processor +
collator, backbone = ViT + LLM (with host prep and uploads), action head = the 4-step flow-matching loop,
E2E = their sum. Ours are medians of 25 warm served requests on trn2 (LNC=2), timed inside the worker with
one extra device sync between backbone and head.

| Platform | Configuration | Data processing | Backbone | Action head | E2E | Frequency | Action MSE vs fp32 |
|---|---|---|---|---|---|---|---|
| H100 (NVIDIA) | PyTorch eager | 6.2 ms | 31.3 ms | 48.2 ms | 85.8 ms | 11.7 Hz | — |
| H100 (NVIDIA) | torch.compile | 6.2 ms | 30.4 ms | 12.0 ms | 48.6 ms | 20.6 Hz | — |
| H100 (NVIDIA) | TensorRT full pipeline | 6.2 ms | 8.8 ms | 12.3 ms | 27.9 ms | 35.9 Hz | — |
| trn2 | 1 NeuronCore, TP=1 | 2.8 ms | 15.7 ms | 32.5 ms | 51.0 ms | 19.6 Hz | 1.72e-5 |
| trn2 | 2 cores, TP=2 action head | 1.9 ms | 19.0 ms | 24.1 ms | 45.0 ms | 22.2 Hz | 1.72e-5 |
| trn2 | 2 cores, TP=2 action head + backbone | 2.0 ms | 14.5 ms | 24.1 ms | 40.5 ms | 24.7 Hz | 1.74e-5 |
| trn2 | 4 cores (one chip), TP=4 action head | 2.0 ms | 19.1 ms | 19.0 ms | 40.2 ms | 24.9 Hz | 1.70e-5 |
| trn2 | 4 cores (one chip), TP=4 action head + backbone | 2.6 ms | 11.6 ms | 18.8 ms | 33.0 ms | 30.3 Hz | 1.71e-5 |

The 1-core and TP=4 head + backbone rows use the default pretransposed weights (below); the three middle rows
were measured before that change (1-core without it: 2.7 / 19.1 / 34.8 / 56.6 ms; TP=4 head + backbone
without it: 35.4 ms).

Action MSE is the normalized action chunk against upstream vLLM-Omni `Gr00tN1d7` in fp32 on CPU, same frame
and initial noise (gate 1e-3; all pass, cosine 0.99999). Request wall time through the offline runner adds
~3-4 ms (IPC) to E2E. Data processing runs on the host CPU; the fast path below is why it is below NVIDIA's.
On one core the graphs alone are ViT 8.6 ms, LLM 7.3 ms, action head 32.1 ms (9.5 / 9.6 / 34.2 ms
before pretransposing the weights). The text buckets start at 160 tokens, so the 156-token LIBERO prompt
no longer pads to 320 (head 36.4 -> 34.2 ms, text 9.9 -> 9.6 ms).

Device profiles (1 core): the action-head graph reads 9.0 GB of HBM per call -- the 2.2 GB of DiT weights
once per denoising step -- at ~0.26 TB/s, and spends ~35% of its TensorE work on transposes (MFU 9%); the
LLM graph is 75% TensorE-active with the same transpose share (MFU 28%). Storing every linear weight as a
contiguous `[in, out]` copy (`GR00T_PRETRANSPOSE`, default `all`; `none` turns it off) removes those
transposes. TP=4 shortens the head less than 4x because it adds 256 all-reduces per call (32 blocks x 2 x 4
steps).

### DROID configuration

Reference input: DROID embodiment, 2 cameras x 2 frames (4 images of 256x256 -> 64 tokens each), a
280-token prompt (bucket 320), 4-step action chunk, BF16, trn2 at LNC=2. Served latency is the warm median of
20 requests through the offline Omni runner (processor, model graphs, action decoding).

| Configuration | Hardware | Model warm latency | Served warm latency | First request (cold compile) |
|---|---|---|---|---|
| TP=1 (recommended for throughput) | 1x trn2 NeuronCore | 60.4 ms | 67.8 ms | ~33 s |
| TP=2 action head (recommended for latency) | 2x trn2 NeuronCores (one chip) | — | 60.0 ms | ~295 s |

Optimization history at that configuration:

| Stage | Before | After | Change |
|---|---|---|---|
| Served request, 1 core | 85.8 ms | 67.8 ms | host fast path + table caches |
| Served request, 2 cores | — | 60.0 ms | TP=2 action head |
| Host processor (upstream `Gr00tPolicy` pre/post-processing, 1 host thread) | 18.5 ms | 7.3 ms | fast path |
| Host processor, 8 host threads (the worker default now) | 15.3 ms | 5.1 ms | fast path + threads |
| Model host prep + uploads (`get_action` minus graphs) | ~1 ms + all tables uploaded per call | 0.8 ms, only pixels/state/noise uploaded | caches |
| Vision tower graph | 15.8 ms | 15.2 ms | — |
| Text decoder graph | 10.4 ms | 9.8 ms | — |
| Action head graph | 37.1 ms | 36.2 ms | — |

What each change does:

- **Host fast path** ([`host_fastpath.py`](../../vllm_omni_neuron/diffusion/models/gr00t/host_fastpath.py)):
  the eval image transform runs once over all frames; the chat-template text and the tokenizer output are
  cached per (instruction, image grid) -- a robot repeats its instruction every step; frames go to the
  Qwen3-VL image processor as tensors instead of PIL images; relative->absolute action decoding is
  vectorized over the horizon instead of one `scipy` pose object per step. The first request of every new
  prompt runs the full upstream processor and is compared field by field with the fast path (any mismatch
  disables it). Model inputs are bit-identical to upstream's; decoded actions agree to float32 rounding
  (max |diff| 6e-8). `GR00T_HOST_FASTPATH=0` turns it off.
- **Host threads:** the diffusion worker runs torch on one thread; the pipeline raises it to
  `model_config.host_threads` / `GR00T_HOST_THREADS` (default 8) around each request.
- **Table caches:** text mRoPE, the causal/padding bias and the image-token gather are cached per prompt;
  vision position taps and RoPE per image grid; their device copies are uploaded once.
- **Camera-count buckets:** the vision graph takes the image count as a compile-time shape. Requests are
  padded with zero images to the next of 1, 2, 3, 4, 6, 8 (`GR00T_IMAGE_BUCKETS`); padded images' tokens are
  never gathered, so actions are unchanged, and a new camera/frame count reuses a compiled graph.
- **TP=2 action head:** attention split by head, the feed-forward by column, one all-reduce after each;
  norms, AdaLN tables and the Euler update stay replicated. Vision and text stay replicated on both cores.

Measured and not adopted: one graph for vision + text (`GR00T_FUSED_BACKBONE=1`, 24.8 ms vs 15.2 + 9.8 ms:
no gain; one fewer launch does not matter at this size); fused Q/K/V projections in the head's
self-attention blocks (`GR00T_HEAD_FUSE_QKV=1`, head 40.1 ms vs 36.2 ms: slower). Earlier rounds: baked AdaLN
modulation tables for the fixed 4-step schedule (see
[`vllm_omni_neuron/diffusion/layers/modulation_tables.py`](../../vllm_omni_neuron/diffusion/layers/modulation_tables.py))
removed 33 linear layers per denoising step and cut the head from 54.9 to 37.1 ms; NKI `attention_cte` for
the vision tower was slower at this sequence length (34 ms vs 15 ms), so it is off by default.

## Known limitations

- No real-time-chunking (RTC) inpainting from a previous action chunk — the upstream `rtc_*` options are
  accepted by the action head's signature but not wired through the Neuron pipeline yet.
- Served one request at a time (`max_batch_size: 1`); for throughput run one TP=1 replica per NeuronCore.
- The action head is ~3x above its weight-streaming floor (32 DiT layers x 4 Euler steps, ~2.2 GB of DiT
  weights per step). TP=2 is the measured lever; TP=4 and in-graph fusions beyond Q/K/V have not been tried.
- A new instruction, image size or camera count pays one full upstream processor call (the fast-path
  self-check) and, for a new text or image bucket, one graph compile.
- GR00T-H-N1.7's own processor and surgical embodiment tags are not available in this plugin — see the next
  section.

## GR00T-H vs N1.7

[GR00T-H-N1.7](https://huggingface.co/nvidia/GR00T-H-N1.7) is NVIDIA's post-train of GR00T N1.7 for surgical
robots, fine-tuned on the [Open-H embodiment dataset](https://huggingface.co/datasets/nvidia/PhysicalAI-Robotics-Open-H-Embodiment).
It is the same architecture family, loaded by the same Neuron pipeline code in this plugin, with these
differences:

| | GR00T N1.7-3B | GR00T-H-N1.7 |
|---|---|---|
| Parameters | 3.144B | 2.943B |
| Action horizon | 40 steps | 50 steps |
| VL self-attention (4-layer transformer before the action head) | present | removed (`use_vl_self_attention: false`) |
| Per-embodiment state dropout | single probability | one probability per embodiment (training-only; not used at inference) |
| Embodiments | OXE/DROID/XDOF/humanoid tags | surgical tags (`jhu_imerse_dvrk`, `cmr_versius`, `rob_surgical_bitrack`, …) |
| Image layout | square crop/target | non-square crop (224×392) / target (236×414), 3 camera views × 1 frame |
| Action representation | the base processor's defaults | fork-only fields (`REL_XYZ_ROT6D`, quaternion state inputs, mean/std normalization, `min_max_embedding_keys`) |

The architecture change (dropping VL self-attention) is handled: the Neuron action head only builds that
block when the checkpoint's config asks for it, so GR00T-H's graph is simply three layers smaller. The
weight-loading, embodiment-conditioned MLPs and the AdaLN-table bake all work unchanged, and the model-level
accuracy gate above passes for GR00T-H (MSE 2.4e-5, cosine 0.99999, with synthetic image-grid inputs).

**What does not work out of the box:** GR00T-H-N1.7's `processor_config.json` uses fields upstream
vLLM-Omni's `ModalityConfig` does not accept (`min_max_embedding_keys`), a representation
(`REL_XYZ_ROT6D`) and quaternion state inputs its state-action processor does not implement, and surgical
embodiment tags absent from its `EmbodimentTag` enum. Serving GR00T-H end to end therefore needs
[NVIDIA-Medtech/GR00T-H](https://github.com/NVIDIA-Medtech/GR00T-H)'s own processor and embodiment-tag code,
which is not vendored into this plugin. The *model* (vision tower, text decoder, action head and their
weight loading) is Neuron-ported and parity-tested at the model level regardless.
